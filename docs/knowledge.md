# Knowledge Layer

The Knowledge layer turns analytics output into structured, reusable facts. It is
the boundary between calculated statistics and human- or AI-readable interpretation.

## KnowledgeFact

`KnowledgeFact` is the public dataclass used by the Knowledge layer. It represents
one reusable fact and includes:

- `category`: stable fact category, normally a `FactCategory` enum value.
- `importance`: relative priority, normally an `ImportanceLevel` enum value.
- `title`: short display label.
- `description`: readable fact text.
- `metadata`: immutable structured values for downstream consumers.
- `confidence`, `tags`, `source`, `date_range`, `severity`, and `insight_type`:
  extension fields for later sprints.

The dataclass remains presentation-independent. Reports, dashboards, and AI prompts
can consume the same fact object without forcing Knowledge to know where the fact
will be displayed.

## Daily Facts

Daily facts describe a single `ListeningSummary`:

- listening time
- playback count
- top artist
- top song

They use `InsightType.DAILY_LISTENING` and are generated by
`KnowledgeEngine.generate_daily_facts()`.

## Trend Facts

Trend facts compare a previous `ListeningSummary` with a current `ListeningSummary`:

- listening time change
- playback count change
- top artist change
- top song change

They use `InsightType.TREND` and are generated by
`KnowledgeEngine.generate_trend_facts()`. Top artist and top song changes are only
emitted when the top item actually changes.

## Insight Facts

Insight facts describe higher-level behavior derived from existing summaries:

- focused listening
- heavy listening
- light listening
- stable favorite

They are generated by `KnowledgeEngine.generate_insight_facts()`. These facts still
come from analytics summaries; the Knowledge layer does not run new database
queries or Spotify calls to discover them.

## Adding Future Insights

Future insight work should follow the existing pattern:

- Add or reuse a `FactCategory` value for the fact's stable identity.
- Choose the appropriate `InsightType`.
- Generate the fact from `ListeningSummary` input only.
- Store machine-readable values in `metadata`.
- Keep presentation formatting and LLM prompting outside the Knowledge layer.
- Add deterministic unit tests for the new fact behavior.

If a future insight needs a new statistic, add that statistic to Analytics first and
then let Knowledge interpret the resulting summary field.
